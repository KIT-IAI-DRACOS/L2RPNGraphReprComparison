# Data Directory

This folder contains pre-computed data that the training pipeline reads at startup. Nothing here is produced during training — these files are generated once (by `setup_envs.py` or offline scripts) and then consumed by the environment wrappers and observation converters.

## Folder Structure

```
data/
├── action_spaces/       # JSON action-space definitions per Grid2Op environment
├── observations_dn/     # Do-nothing policy observation statistics (mean/std) for normalisation
└── scaling_arrays/      # Per-feature min/mean/max arrays used by the ObservationConverter
```

---

## `action_spaces/`

Each subfolder corresponds to a Grid2Op scenario (matched by the environment name used in Grid2Op). The JSON files list which substation bus-switching actions are available to the RL agent.

```
action_spaces/
├── l2rpn_case14_sandbox/    # IEEE 14-bus
├── l2rpn_wcci_2020/         # IEEE 36-bus (WCCI 2020)
└── l2rpn_wcci_2022/         # IEEE 118-bus (WCCI 2022)
```

The action space file to load is selected via the `env` config group (e.g. `configs/rllib/env/case14.yaml`).

### 14-bus action space files

| File | Description |
|---|---|
| `medha.json` | **Default for 14-bus.** 6 high-impact substation reconfigurations curated by Medha Subramanian. Covers the most impactful bus-switching actions while keeping the action space tractable. |
| `medha_reversed.json` | Same actions as `medha.json` with reversed bus assignments. |
| `assym.json` | Asymmetric action space — includes asymmetric bus-switching topologies. |
| `tennet.json` | Action space used in TenneT-related experiments. |
| `d3qn2022.json` | Action space used for D3QN (2022 competition variant). |
| `rl2grid_bus14_0.json` / `rl2grid_bus14_1.json` | Action spaces generated by the rl2grid tool at different complexity levels (0 = smallest, 1 = larger). |

### 36-bus and 118-bus action space files

Files follow the naming pattern `rl2grid_bus{N}-M_{level}.json`, where the level index (0–4) controls action space size — larger indices include progressively more substation configurations:

| Level | Approx. size | Use case |
|---|---|---|
| `_0` | ~8 KB | Minimal, fastest to train |
| `_1` | ~50 KB | Small |
| `_2` | ~300 KB | Medium |
| `_3` | ~2 MB | Large |
| `_4` | ~12 MB | Full action space |

## `observations_dn/` and `scaling_arrays/`

> **Note: these folders are not used by the current codebase.**

Both `ObservationConverter` implementations (`GraphObservationConverter` and `FlatObservationConverter`) normalise observations **online** using gymnasium's `RunningMeanStd`, which updates its mean and variance estimate from the live observation stream during training. No pre-computed statistics are loaded from disk.

These folders are likely leftovers from an earlier version of the pipeline (or the integrated `rl4pnc` baseline) that pre-computed offline normalisation statistics under a do-nothing rollout. They can be ignored unless a future converter is written that loads pre-computed statistics.
